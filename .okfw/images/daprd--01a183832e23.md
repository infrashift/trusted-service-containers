# daprd

daprd is the Dapr sidecar runtime. We build it from source onto `ubi9-micro`, with all components. It replaces the official daprd with no other change.

## Track

Build track. We compile `daprd` from the pinned `sources.dapr` commit with `Containerfiles/daprd.Containerfile`. Dapr publishes no UBI variant. See [Build track](/architecture/build-track--01a18382f2d2.md).

One Dapr source produces the three images [daprd](/images/daprd--01a183832e23.md), [dapr-placement](/images/dapr-placement--01a183832e48.md) and [dapr-scheduler](/images/dapr-scheduler--01a183832e6e.md). `sources.dapr.lockstep` keeps them on the same commit. The source track is the 1.18 minor line. The platform moved up from 1.14. Version 1.14 is outside the Dapr N-2 support window.

## Trust class

`internal`. We verify our `ubi9-micro` base against the release key of `infrashift/trusted-base-images`. See [Upstream trust classes](/architecture/upstream-trust-classes--01a18382f3fb.md).

The binary cross-check compares our binary with the binary in `docker.io/daprio/daprd`, trust class `none`, tier `best-effort`. It pins per-platform tags. Thus the extraction never depends on the resolution of a manifest list at run time. See [ADR-004: Dual provenance is an observation, not a gate](/decisions/adr-004-dual-provenance-is-an-observation-not-a-gate--01a18382f4a6.md).

## Enforcement

See `versions.json` for the current value. On 2026-10-28 the value was `enforce`.

## Variants and platforms

One variant, `runtime`. Architectures: `amd64`, `arm64`. The upstream manifest list also has windows/amd64 and linux/arm/v7. We do not build them.

## Runtime

* Ports: 3500, 50001, 50002, 9090. These come from the documentation, not from the pinned source. Before you rely on them, verify them against the options in cmd/daprd.
* Entrypoint: /usr/bin/daprd. A compatibility symlink /daprd exists, because the Dapr injector can emit the command /daprd.
* User: 1001. The upstream image runs as 65532, and the Dapr Helm chart pins `runAsUser: 65532`. A Helm deployment needs an override.

## Notes

* The build must use `-tags allcomponents`. Without a component tag, daprd compiles but panics at its first start. The `--version` smoke test found this defect before the first release of the image.
* `allcomponents` matches the upstream default. Thus the image can replace the official image with no other change. `stablecomponents` has a smaller attack surface, but it removes components that some users need. Change the tag only as a deliberate decision.
