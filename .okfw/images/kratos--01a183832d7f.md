# kratos

kratos is Ory Kratos, the identity and user management server. We build it from source, because no official UBI-based Ory image exists.

## Track

Build track. We compile `kratos` from the pinned `sources.ory` commit onto our `ubi9-micro` base, with `Containerfiles/kratos.Containerfile`. Ory publishes no UBI-based image. See [Build track](/architecture/build-track--01a18382f2d2.md).

One shared tag releases the four Ory images in lockstep. The source track is the v26 release line. A partial bump is a defect. `drift-upstream.yml` must propose all four images together.

## Trust class

`internal`. The upstream signature that we verify is the signature of our `ubi9-micro` base, against the release key of `infrashift/trusted-base-images`. See [Upstream trust classes](/architecture/upstream-trust-classes--01a18382f3fb.md).

The binary cross-check compares our binary with the binary in `docker.io/oryd/kratos`, trust class `none`, tier `best-effort`. Ory signs with cosign, but the signature has `Cert: false` and `Chain: false`, and Ory publishes no public key. Thus we pin the vendor image by digest and do not claim to verify it. See [ADR-004: Dual provenance is an observation, not a gate](/decisions/adr-004-dual-provenance-is-an-observation-not-a-gate--01a18382f4a6.md).

## Enforcement

See `versions.json` for the current value. On 2026-10-28 the value was `enforce`.

## Variants and platforms

One variant, `runtime`. Architectures: `amd64`, `arm64`.

## Runtime

* Ports: 4433 and 4434.
* Command: `kratos serve`.
* User: 1001, with tzdata.
* Build: `CGO_ENABLED=0`, `-tags=json1`, `-s -w`. The ldflags stamp the version, the commit and the date.

## Notes

* The cross-check uses the `-distroless` tag of each architecture, not the bare release tag. The bare tag is an Alpine and musl build with `CGO_ENABLED=1` and the tags `sqlite`, `hsm` and `json1`, with user 10000. It is not comparable to our build.
* The image declares a volume at /var/lib/sqlite.
