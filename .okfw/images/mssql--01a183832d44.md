# mssql

mssql is Microsoft SQL Server 2025 on a RHEL 10 base. We mirror it from MCR and verify its Notary Project signature.

## Track

Mirror track, from `mcr.microsoft.com/mssql/rhel/server`. We chose the RHEL repository, not the Ubuntu `mssql/server` repository, to match the UBI posture of this repository. See [Mirror track](/architecture/mirror-track--01a18382f29c.md).

## Trust class

`notation`. The image has a Notary Project signature as an OCI referrer. It chains to the Microsoft Supply Chain RSA Root CA 2022. See [Pinned upstream keyrings and identities](/architecture/pinned-upstream-keyrings-and-identities--01a18382f417.md).

* On 2026-09-11, we pinned the root by TOFU from the Microsoft PKI endpoint, as `.github/pdp/keyring/microsoft-supply-chain-rsa-root-ca-2022.crt`. The root is valid until 2047-02-17.
* The signing leaf is `CN=Microsoft SCD Products RSA Signing`. It chains through `CN=Microsoft SCD Products RSA CA` and expires on 2027-10-31.
* `notation.trustedIdentity` in `versions.json` pins the leaf subject. The root alone would trust each Microsoft product signature.
* On 2026-09-11, we verified the signature locally at the level `strict`. A wrong root, a wrong identity and a registry outside the scope each failed, as expected.
* The image has no cosign signature and no SBOM or provenance referrer. Thus the policy requires no attestations of this class.

WARNING: The signing leaf expires on 2027-10-31. Check the pinned identity again before that date. `NOTATION_ROOT_DRIFT` shows a rotation of the root.

## Enforcement

See `versions.json` for the current value. On 2026-10-28 the value was `observe`.

The image stays in `observe` mode until a person records the day-one CVE triage in `.github/pdp/exceptions.yaml`. It is a RHEL image of about 700 MB.

## Variants and platforms

One variant, `runtime`, with the tag `2025-latest`. Platform: `linux/amd64` only.

* Microsoft supports only x86-64 hosts. Microsoft says that it does not test emulation.
* The tag resolves to a bare manifest with no index. `scripts/manifest-platforms.sh` gets the platform from the config.
* The track is the exact tag. Microsoft moves `2025-latest` on each CU and GDR. Only the digest changes.
* A CU regex track would be a trap. `sort -V` puts a GDR tag before its CU tag, so `scripts/drift-upstream.sh` would never propose a GDR security release.
* We saw the first move of the tag on 2026-09-15, from a GDR to a CU. It confirmed the expected shape.

## Notes

* The container starts only with `ACCEPT_EULA=Y` and a password in `MSSQL_SA_PASSWORD`, given at run time.
* The default of `MSSQL_PID` is the developer edition. If you select a production edition, you assert that you hold a licence.
* The image runs as the user `mssql` on port 1433. It declares no volume. Mount a volume at /var/opt/mssql for the data.
* The tag does not show the SQL build number. Read the label `com.microsoft.version` from the evidence.
* MCR allows anonymous pulls, so the pipeline has no login step for it.
