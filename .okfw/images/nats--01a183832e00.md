# nats

nats is the NATS messaging server with JetStream. No official UBI variant exists. Thus we build it from source onto `ubi9-micro`, with our own configuration.

## Track

Build track. We compile `nats-server` from the pinned `sources.nats` commit with `Containerfiles/nats.Containerfile`. The source track is the 2.14 minor line. Before this image, the platform used the 2.11 Alpine image. See [Build track](/architecture/build-track--01a18382f2d2.md).

The build flags copy the upstream `.goreleaser.yml`: `-trimpath`, `CGO_ENABLED=0` and `-w` (not `-s -w`). The ldflags stamp the tag and the short commit. `versions.json` pins the short commit as `shortCommit`. The reason is that the vendor stamps the dynamic abbreviation of git, which has 9 characters.

`GOTOOLCHAIN` is `local`, not the upstream Go version. The upstream Go version had `stdlib` advisories that block under our policy. Only a different compiler could clear them. See [Toolchain pins](/architecture/toolchain-pins--01a18382f31f.md).

## Trust class

`internal`. We verify our `ubi9-micro` base against the release key of `infrashift/trusted-base-images`. See [Upstream trust classes](/architecture/upstream-trust-classes--01a18382f3fb.md).

The binary cross-check compares our binary with the binary in `docker.io/library/nats`, tier `best-effort`. The cross-check sets its own trust class for the vendor image: `docker-official`. This value is not an `upstreamTrust` class. See [ADR-004: Dual provenance is an observation, not a gate](/decisions/adr-004-dual-provenance-is-an-observation-not-a-gate--01a18382f4a6.md).

* The tier was `flag-matched`. After a test on 2026-08-18, we lowered it to `best-effort`. We matched each build input that `go version -m` shows, but the binary still differed. Until a person finds the remaining input, a NATS mismatch is not an alarm.
* NATS has a second, independent anchor. The official image downloads the GitHub release tarball and verifies a sha256 in its Dockerfile. `versions.json` holds these hashes as `crosscheck.releaseTarballSha256`.
* On 2026-08-18 and again on 2026-10-28, the hashes matched the release `SHA256SUMS` and the vendor Dockerfile. The binary in each official image was byte-identical to the binary in its tarball.

## Enforcement

See `versions.json` for the current value. On 2026-10-28 the value was `enforce`.

## Variants and platforms

One variant, `runtime`. Architectures: `amd64`, `arm64`. The upstream also publishes arm/v6, arm/v7, 386, ppc64le, s390x and loong64. We do not build them.

## Runtime

* Ports: 4222 (clients), 8222 (HTTP monitoring), 6222 (cluster). All are above 1024, so user 1001 can bind them.
* Volume: /var/lib/nats. JetStream keeps its data in a `jetstream` directory below it. Without a persistent mount, a restart loses all streams and consumers. Nothing shows the problem before the restart.
* Command: `nats-server --config /etc/nats/nats-server.conf`. A compatibility symlink /nats-server points to the binary.

## The configuration is ours

The image holds `rootfs/nats/etc/nats/nats-server.conf`. We wrote this file ourselves. CODEOWNERS covers it. The upstream nats-docker configuration has a cluster block with hardcoded credentials. An image called "trusted" must not hold them.

* `server_name` comes from the environment variable `NATS_SERVER_NAME`. Thus each pod of a StatefulSet can have a stable identity.
* The monitoring endpoint on 8222 has no authentication. Bind it to a private interface or put it behind a NetworkPolicy.
* The configuration sets JetStream limits and connection limits.
* The configuration has no `authorization`, `accounts` or `operator` block.

WARNING: By default, NATS gives open access on port 4222. Before you expose the server outside a trusted network, supply an authentication model.

The configuration also has no cluster, gateway or leaf-node routes, and no inbound TLS. Add them in your own mounted configuration. The image has a CA trust bundle, so outbound TLS verification works.

To use your own configuration, mount it over /etc/nats/nats-server.conf. Alternatively, pass `-c` with your path.
