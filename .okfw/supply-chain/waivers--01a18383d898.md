# Waivers

A waiver is one entry in `.github/pdp/exceptions.yaml`. It is an accepted risk with an owner and an end date. It is not a way to make a red check green. The PDP reads the file, so the file is the only place where a waiver lives.

## Fields

Every field is required.

| Field | Rule |
|---|---|
| `id` | `EXC-YYYY-NNNN`. Each id must be unique (`EXCEPTION_DUPLICATE_ID`). |
| `image` | A key in the `images` map of `versions.json`. Otherwise `EXCEPTION_ORPHANED` denies. |
| `variant` | `"*"` or an exact variant name. |
| `package` | `"*"` or an exact package name. |
| `cves` | A non-empty list. One waiver can cover a batch that has one rationale. |
| `issued` | An RFC 3339 time. |
| `expires` | An RFC 3339 time after `issued`, and 90 days or less after it. |
| `owner` | The person who accepts the risk, for example `@ryancraig`. |
| `ticket` | A string. The PDP checks only that it exists. By convention it is a URL: for a new waiver, the GitHub URL of the wiki issue on `main`. |
| `justification` | 40 characters or more of real reasons. The PDP counts the characters after it removes leading and trailing spaces. |

## Rules that the PDP enforces

1. A waiver that has a missing field, a short justification, or a bad date waives nothing. For example, an entry with no `expires`, or with `expires: "n/a"`, waives nothing. The PDP reports `EXCEPTION_INVALID`, so the author can see the cause.
2. The maximum window is 90 days from `issued`, for every image and every trust class.
3. The PDP compares `expires` with `input.evaluated_at`, which the caller supplies. It never reads a clock, so a decision replays the same way later.
4. A waiver that expires in 14 days or less gives the warning `EXCEPTION_EXPIRING_SOON`.
5. An expired waiver gives `EXCEPTION_EXPIRED` and stops waiving. The finding blocks again.
6. A waiver can only move a CVE finding from `blocking` to `waived`. No integrity, signature or label rule reads it.

## The ticket and the wiki

The wiki is the tracker of record. For a new waiver, record a wiki issue first. Then set `ticket` to the GitHub URL of that issue on `main`, for example `https://github.com/infrashift/trusted-service-containers/blob/main/.okfw/issues/<file>.md`.

Older waivers point at GitHub issues. Their wiki issues give the GitHub number in `x.github`. A finding concept in `findings/` records each group of waivers with the same ticket and expiry, and goes stale on the expiry date.

## What the wiki does not hold

Do not copy a waiver into the wiki. Give its id, for example `EXC-2026-0017`. The file stays the source of truth.
